# Uncommitted changes review

1. Inspect `git status --short`, `git diff --no-ext-diff --no-textconv --`, `git diff --cached --no-ext-diff --no-textconv --`, and `git ls-files --others --exclude-standard -z`. A clean tree means nothing to review.
2. Review staged and unstaged layers separately, and examine the combined `git diff --no-ext-diff --no-textconv HEAD --` for final working-tree behavior when HEAD exists. Do not merely concatenate two patches and treat their line numbers as one patch: a staged change may be overwritten by an unstaged change. For an unborn branch, use index additions and working-tree contents as the baseline-free snapshot.
3. Read untracked files without staging them. Respect ignore rules; do not dump secrets or binary content. Inspect relevant configuration/templates/assets even when no JS/TS files changed. Explicitly disclose binary, generated, oversized, or otherwise uninspected files.
4. Read staged context via `git show :<path>` and working context from disk; attach each finding to its layer and correct line coordinates. If a staged-only bug has already been corrected in the working tree, explain that the staged snapshot still contains it instead of describing the current file as broken. Handle deleted/renamed files using baseline context.
5. Detect concurrent changes before validation or fixes and refresh the affected snapshot. Preserve the index and unrelated edits. Fixes authorized for this mode go into the working directory; do not stage or commit them unless requested, and explain if an existing staged finding remains in the index.
